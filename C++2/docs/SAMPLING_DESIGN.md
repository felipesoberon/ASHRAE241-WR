# Sampling Design

## Scope and non-equivalence

C++2 implements **aggregate-demand-conditioned marginal one-dimensional LHS**. The design is an independently specified alternative to the sampling procedure described by Jones et al. (2025).

Each complete named bank contains one jittered sample in every one-dimensional stratum, followed by a deterministic shuffle. This provides marginal stratification only. Simulation-level tuples, within-infector parameter vectors, susceptible–infector pairings, multi-infector QER sums, and event-selected prefixes are not joint-stratified. Infector-count outcomes are produced by inverse-transforming one complete marginal LHS; subsets selected by a particular count are not separately stratified. The design is neither a multidimensional joint LHS nor a grouped LHS.

Jones et al. describes a matrix of uniformly distributed random numbers produced by LHS in MATLAB/Excel, but does not publish its dimensions, seed, column mapping, dependence structure, or exact software behavior. C++2 is therefore not demonstrated publication-equivalent. Jones also states that occupants use identical PBR, whereas C++2 assigns separate person-specific PBR values to the susceptible and every infector.

## Portable random primitives

Every model stream uses `std::mt19937_64` initialized with one derived 64-bit stream seed. C++2 does not use `std::uniform_real_distribution` or `std::shuffle` for model sampling.

For a raw engine output `x`, the open-unit conversion is:

```text
m = x >> 11
u = (m + 0.5) / 2^53
```

The implementation uses `std::nextafter` to nudge a rounded endpoint back inside its stratum. Every returned uniform and LHS point is finite and strictly inside `(0, 1)`.

For a nonzero bound `b`, an unbiased integer in `[0, b)` is generated by threshold rejection:

```text
threshold = uint64_t(0 - b) % b
do x = engine() while x < threshold
return x % b
```

Fisher–Yates iterates `i` from the vector length down to `2`, draws `j` in `[0, i)`, and swaps elements `i - 1` and `j`. Jitter generation and shuffling continue from the same engine state.

For a bank of length `n`, `generate_lhs_1d` creates one value strictly inside each stratum `(i/n, (i+1)/n)` and then applies that shuffle. A zero-length bank is not generated and receives no seed.

## Infector-count plan

For each replicate, one LHS of length `N` is derived on stream `infector_count`. Each uniform is transformed with the binomial inverse CDF:

```text
ninf_i = BinomialPPF(u_i; I0, p)
```

This is one `Binomial(I0, p)` infector-count marginal per simulation, where `I0` is effective occupancy and `p` is effective community infection rate. The complete vector is fixed before any other parameter bank is created.

The plan records:

- `N_zero`: rows where `ninf_i == 0`
- `N_active`: rows where `ninf_i > 0`
- `K_total`: the checked sum of all positive `ninf_i`

A zero-infector row is assigned exact positive `+0.0` ECAi before any other draw is requested. It consumes no susceptible or infector-bank values and executes no QER or ECAi equation.

## Exact-size parameter banks

The 11 named parameter banks are built in this fixed order:

| Bank | Stream ID | Length | Transform |
| --- | ---: | ---: | --- |
| `susceptible_pbr` | 1 | `N_active` | category PBR lognormal GM/GSD |
| `gamma` | 2 | `N_active` | Uniform(0.42, 0.61) |
| `lambda` | 3 | `N_active` | lognormal GM 0.52, GSD 1.9 |
| `infector_pbr` | 4 | `K_total` | category PBR lognormal GM/GSD |
| `c_drop` | 5 | `K_total` | category C_drop lognormal GM/GSD |
| `d_bar` | 6 | `K_total` | category d̄ lognormal GM/GSD |
| `E` | 7 | `K_total` | scaled Beta(5, 2) on [2, 5] |
| `GVL` | 8 | `K_total` | base-10 lognormal μ 7.0, σ 1.4 |
| `VF` | 9 | `K_total` | scaled Beta(5, 2) on [1e-4, 1e-2] |
| `RTD` | 10 | `K_total` | Uniform(0.43, 0.65) |
| `DK` | 11 | `K_total` | Uniform(5, 15) |

Each bank is one complete one-dimensional LHS with its own stream ID, exact length, and seed. The susceptible and infector PBR banks are distinct even though they use the same category distribution. No realized value is shared between roles or between infectors.

## Stable assignment and evaluation

A consumption ID packs an 8-bit bank ordinal into the high bits and a 56-bit bank index into the low bits:

```text
consumption_id = (bank_ordinal << 56) | index
```

Bank lengths are checked against the 56-bit index capacity. IDs are stable for a fixed plan and unique across the 11 banks.

Assignment is materialized once in ascending simulation-index order before model evaluation:

1. A zero-infector row advances no cursor.
2. An active row consumes the next value from each of the three susceptible banks.
3. It then consumes the next value from each of the eight infector banks for each infector, in infector-list order.
4. `ParameterCursor::finalize` requires every cursor to equal its planned bank length.

The cursor is forward-only and single-use; there is no reset, rewind, refill, append, or second traversal. Overrun and under-consumption are errors. The fully materialized assignment permits forward, reverse, or interleaved evaluation schedules without changing person-to-value identity or output positions. Infector QER values within a row are always summed in list order. Production uses forward evaluation.

## Checked resource formulas

All relevant size and policy checks precede allocation.

The infector-count planning peak is:

```text
16N + 16(I0 + 1) bytes
```

This is one `N`-double uniform vector, one `N`-element `long long` count vector, and the two `(I0 + 1)`-double binomial buffers (the transient PMF and the retained CDF) of the per-replicate `BinomialPpfTable`, which builds the constant `(I0, p)` inverse CDF once and resolves every `u` against it with exactly the single-shot `binomial_ppf` result.

The combined accounting for the retained count vector and parameter banks is:

```text
8[N + 3N_active + 8K_total] bytes
```

The implementation checks `N * I0` as the maximum possible `K_total`, every multiplication and addition for `size_t` overflow, vector maximum sizes, `N <= 2^29`, `K_total <= 2^29`, and both formulas against the 4 GiB policy. These are engineering limits, not Jones values. The CLI exposes the `N` ceiling but has no resource-budget override flag.

## Seed tuple and fingerprint

Sampling design version `1` and seed-policy version `CPP2-SEED-v1` are current. Each stream seed is derived from this ordered tuple:

```text
(base_seed,
 design_version,
 effective_configuration_fingerprint,
 replicate_index,
 stream_id,
 list_length)
```

The configuration fingerprint covers the canonical category name, `I0`, volume, mask efficiency, community rate, target probability, duration, percentile, confidence level, `N`, and `R`, in that order. The canonical ASCII serialization and exact FNV-1a/SplitMix64 fold are defined in [`SEED_POLICY.md`](SEED_POLICY.md). The list length is part of the tuple, so changing realized aggregate demand changes the downstream bank seeds.

## Reproducibility boundary

The integer seed fold, `mt19937_64` outputs, threshold-rejection bounded integers, and Fisher–Yates index permutation use standard-defined integer behavior and explicit algorithms. Bit identity for the open-unit conversion, `nextafter` corrections, binary64 stratum arithmetic, shuffled double values, transformed values, and end-to-end output requires supported IEEE-754 binary64 semantics plus the same relevant compiler, standard and mathematical libraries, target architecture, and floating-point flags. It is not guaranteed by conformance to C++17 alone.

CMake disables fast-math and floating-point contraction with `-fno-fast-math -ffp-contract=off`. Across other toolchains, transformed values are assessed with the tolerances in [`MODEL_SPECIFICATION.md`](MODEL_SPECIFICATION.md#115-validation-acceptance-table), not assumed bit-identical.

## Risk-averse conditional infector sampling

The optional `risk-averse` infector policy samples the binomial distribution conditional on `X >= 1`. It uses the existing `infector_count` LHS stream exactly once per requested simulation and a conditional PPF in CDF space; it does not redraw zero-infector values and does not materialize an affine floating-point cutoff. The helper starts at count 1, handles `p=1` and `zero_mass==1` explicit branches, and records the zero mass and algorithm/branch provenance.

The default `community` policy is unchanged and retains zero-infector rows. Risk-averse plans require `I0>=1` and `p>0`, have `n_zero=0`, `n_active=N`, and `K_total>=N`. The policy is an estimand change—conditional risk given at least one infector—not a joint LHS and not a custom category-input override.
